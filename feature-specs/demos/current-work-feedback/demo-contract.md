## 比较变量

相同任务、步骤、输入与反馈下，切换“右侧查看 / 消息内展开”。默认推荐右侧查看：正文与证据并排，折回不丢聊天位置。消息内展开适合短过程，但长输入会拉长对话。窄屏的侧边查看变成可返回的详情层，不将三列挤成窄条。

## 场景与最小证据

| 场景 | 主画面 | 可操作证据 |
|---|---|---|
| 安静默认态 | 用户问题、猫简短进展、一行“查看过程” | 不开面板也知道当前动作；没有实时总分 |
| 主动作 | 展开关键步骤，点击读取 skill 的步骤 | 原文/版本/实际读取的不同信息可见；不以目录名字代替使用证据 |
| 本次输入 | 选择输入渠道，逐段展开示例文本 | Provider 内部内容明确不可见；不伪装“完整输入” |
| 完成反馈 | 正文答复 + 目标、验证、剩余缺口 | skill 净收益因无对照而未知，不显示假总分 |
| 来源暂不可读 | 已有步骤保留，输入区显示错误与重读 | 重读只恢复预设 fixture，明确不是重跑模型 |
| 无记录 | 正文可读，过程显示“没有可核验记录” | 不猜成没做过或给 0 分 |
| 折叠/布局/窄屏 | 原选项和输入草稿保留在当前页面 | 陌生草稿 sentinel 在打开、切 tab、关闭后不丢 |

## 交互边界

- 真正实现：打开/关闭过程、查看步骤详情、切换输入/反馈、切换布局、窄屏退化、当前页草稿保留、fixture 读取恢复。
- 未实现：消息发送、生产身份/权限、真实评测、自动采集、跨刷新恢复、多 Agent 执行、产品主壳和正式编辑器。
- 草稿是普通 textarea，发送按钮禁用并明示此草图不发送。没有把它称作聊天引擎或文档编辑器。
- 无自动时间轴，场景只由演示控制选择；不需要播放/暂停，没有计时器后台推进。
- 开发控制条与产品区域分离，可隐藏；固定的原型诚实标签仍保留。
